# 📚 Claude Code Documentation Hub

## Обзор структуры /cc/

Директория `/cc/` содержит всю рабочую документацию проекта Screen Translator v2.0, организованную для эффективной работы с Claude Code.

## 📁 Структура директорий

### `/cc/tasks/` - Управление задачами
- **Дневные логи:** `YYYY-MM-DD.md` - выполненные задачи с временными метками
- **TODO списки:** `TODO_<topic>.md` - задачи по категориям
- **Completed:** `completed/` - архив выполненных задач

**Текущие файлы:**
- `2025-08-23.md` - Сегодняшний лог работы
- `TODO_critical_fixes.md` - Критические исправления (P0, P1, P2)

### `/cc/docs/` - Техническая документация

#### `architecture/` - Архитектурная документация
- `system_design.md` - Полное описание архитектуры v2.0
- `architecture_notes.md` - Заметки и решения по архитектуре

#### `patterns/` - Паттерны проектирования
- `implemented_patterns.md` - 17 реализованных паттернов с примерами

#### `guides/` - Руководства
- `development_workflow.md` - Полное руководство по разработке

### `/cc/analysis/` - Анализ и метрики

#### `reports/` - Отчеты
- `project_evolution.md` - История эволюции проекта v1.0 → v2.0
- `architecture_metrics.md` - Метрики архитектуры и качества кода

## 🔧 Использование документации

### Для Claude Code
```python
# При работе с задачей - обновить лог
Write("/workspace/cc/tasks/2025-08-23.md", 
      content="## [HH:MM] Задача - Описание")

# При нахождении проблемы - создать TODO
Write("/workspace/cc/tasks/TODO_new_issue.md",
      content="# TODO: Описание проблемы")

# При архитектурном решении - документировать
Write("/workspace/cc/docs/architecture/new_decision.md",
      content="# Архитектурное решение: ...")
```

### Для разработчика
1. Проверять TODO списки перед началом работы
2. Вести дневной лог выполненных задач
3. Документировать архитектурные решения
4. Обновлять метрики после значимых изменений
