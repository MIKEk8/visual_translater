## Screen Translator v2.0

**Pipeline Version**: 1.0

---

## 🎯 Pipeline Overview

This GitLab CI/CD pipeline provides comprehensive automation for Screen Translator v2.0, including:

- **Multi-Python version testing** (3.8, 3.11, 3.12)
- **Quality assurance** (formatting, linting, type checking, security)
- **Comprehensive testing** (unit, integration, architecture)
- **Security scanning** (code analysis, dependency vulnerabilities)
- **Build automation** (Python packages + executable)
- **Deployment management** (staging/production environments)

### **8 Pipeline Stages:**
```
1. validate      → Configuration validation
2. dependencies  → Python environment setup  
3. quality       → Code quality checks
4. test          → Testing suite execution
5. security      → Security scanning
6. build         → Package/executable creation
7. deploy        → Environment deployment
8. cleanup       → Resource cleanup
```

---

## 📋 Stage Details

### **Stage 1: Validation**
**Purpose**: Validate project configuration before proceeding

**Jobs:**
- `validate-config` - Check for required files (requirements.txt, pyproject.toml)

**Triggers**: All pushes except scheduled

**Failure Impact**: Stops entire pipeline

---

### **Stage 2: Dependencies** 
**Purpose**: Set up Python environments and install dependencies

**Jobs:**
- `install-deps-py38` - Python 3.8 environment
- `install-deps-py311` - Python 3.11 environment  
- `install-deps-py312` - Python 3.12 environment

**Features:**
- Virtual environment creation
- Dependency caching for faster builds
- Development + build dependencies installation

**Artifacts**: Virtual environments (1 hour retention)

---

### **Stage 3: Quality Checks**
**Purpose**: Ensure code quality and style compliance

**Jobs:**
- `code-formatting` - Black code formatter check (**BLOCKING**)
- `import-sorting` - isort import organization (**BLOCKING**)  
- `style-guide` - Flake8 style guide compliance (**BLOCKING**)
- `type-checking` - MyPy type checking (allow failure)
- `code-complexity` - Radon complexity analysis (allow failure)
- `dead-code-detection` - Vulture dead code detection (allow failure)

**Quality Gates**: First 3 jobs MUST pass for pipeline to continue

---

### **Stage 4: Testing**
**Purpose**: Comprehensive test suite execution

**Jobs:**
- `unit-tests-py38` - Python 3.8 unit tests with coverage
- `unit-tests-py311` - Python 3.11 unit tests with coverage  
- `unit-tests-py312` - Python 3.12 unit tests with coverage
- `integration-tests` - Integration tests with Tesseract
- `architecture-tests` - Architecture compliance validation

**Features:**
- Code coverage reporting (80% target)
- JUnit XML reports for GitLab integration
- HTML coverage reports
- Architecture compliance validation (circular dependencies, interfaces)

**Coverage Threshold**: 80% minimum

---

### **Stage 5: Security**
**Purpose**: Security vulnerability detection

**Jobs:**
- `security-scan` - Bandit + Safety security analysis

**Features:**
- Static Application Security Testing (SAST)
- Dependency vulnerability checking
- JSON report generation
- GitLab Security Dashboard integration

**Allow Failure**: Yes (for initial deployment)

---

### **Stage 6: Build**
**Purpose**: Create distributable artifacts

**Jobs:**
- `build-package` - Python wheel/source distribution
- `build-executable` - PyInstaller Windows executable (manual trigger)

**Artifacts:**
- Python packages (.whl, .tar.gz) - 1 month retention
- Windows executable - 1 month retention

---

### **Stage 7: Deploy**
**Purpose**: Deploy to target environments

**Jobs:**
- `deploy-staging` - Deploy to staging (develop branch, manual)
- `deploy-production` - Deploy to production (main/master branch, manual)

**Environments:**
- Staging: https://staging.screen-translator.local
- Production: https://screen-translator.com

**Deployment Strategy**: Manual approval required

---

### **Stage 8: Cleanup**
**Purpose**: Clean up temporary resources

**Jobs:**
- `cleanup-cache` - Remove temporary files and caches

**Trigger**: Always runs (even on pipeline failure)

---

  - **Scope**: All tests with detailed coverage

## ⚙️ Configuration Variables

### **Global Variables**
```yaml
PIP_CACHE_DIR: "$CI_PROJECT_DIR/.cache/pip"
PYTEST_CACHE_DIR: "$CI_PROJECT_DIR/.cache/pytest"  
MYPY_CACHE_DIR: "$CI_PROJECT_DIR/.cache/mypy"
MIN_COVERAGE: "80"
MAX_COMPLEXITY: "10"
```

### **Caching Strategy**
**Cache Key**: Based on requirements.txt and pyproject.toml
**Cached Paths**:
- Python pip cache
- Pytest cache  
- MyPy cache
- Virtual environments

**Benefits**: ~50% faster pipeline execution after initial run

## 🎯 Pipeline Triggers

### **Automatic Triggers**
- **Push to any branch**: Full pipeline (except manual jobs)
- **Merge Requests**: Full pipeline for validation
- **Scheduled**: Nightly comprehensive testing

### **Manual Triggers**
- **Executable Build**: `build-executable` job
- **Staging Deploy**: `deploy-staging` job  
- **Production Deploy**: `deploy-production` job
- **Performance Tests**: `performance-test` job
- **Quality Report**: `quality-report` job

### **Branch-Specific Behavior**
- **develop**: Can deploy to staging
- **main/master**: Can deploy to production  
- **feature/***: Full testing, no deployment

## 📊 Quality Gates & Thresholds

### **Blocking Quality Gates**
1. **Code Formatting**: Must pass Black formatting check
2. **Import Sorting**: Must pass isort check  
3. **Style Guide**: Must pass Flake8 linting
4. **Configuration**: Must have required config files

### **Quality Thresholds**
- **Test Coverage**: ≥80% required
- **Code Complexity**: ≤10 cyclomatic complexity recommended
- **Security**: No high/critical vulnerabilities in production

### **Architecture Requirements**
- **No Circular Dependencies**: Architecture tests verify
- **Interface Compliance**: TrayManager → ITrayManager
- **DI Container**: Must have required methods

## 🛠️ Local Development Integration

### **Pre-Commit Simulation**
```bash
# Simulate quality checks locally
black --check src/
isort --check-only src/  
flake8 src/
mypy src/ --ignore-missing-imports
```

### **Local Testing**
```bash
# Run same tests as pipeline
python -m pytest src/tests/unit/ --cov=src --cov-report=term
python -m pytest src/tests/integration/ -m "not gui"
```

### **Security Scanning**
```bash
bandit -r src/ -ll
safety check
```
